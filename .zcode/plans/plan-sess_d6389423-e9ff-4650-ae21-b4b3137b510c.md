# 导入性能优化计划

## 先回答两个问题

**1. 是否依赖上游？** 基本不依赖。上游库（amulet-core、PyMCTranslate、litemapy）只负责「文件 → (坐标, 方块字符串)」这一段，之后的 mesh 构建、材质、几何节点实例化全是自有代码。且瓶颈主要出在我们自己的调用方式上：同一方块字符串被重复调用 `from_universal` 翻译上百万次、`get_version()` 在三重循环内反复查找、逐顶点纯 Python 写属性。已核实 amulet-core 1.9.44 **没有**官方批量 `get_blocks` API，但可以通过「按唯一字符串缓存翻译结果」把百万次翻译降为几十次，或走 chunk 级 numpy 读取绕开——都不需要等上游发版，也不受 cp313 死结影响。

**2. 具体如何优化？** 分三档（用户已确认全做，覆盖 litematic + amulet 两条路径）。

## 第一档：低风险快速收益

1. **翻译缓存 + 循环外提**（`codes/schem.py:102-124`、`schem.py:273-330`、`codes/importfile.py:947+`）
   - `get_version(platform, version)` 提到三重循环外（当前每格执行一次）
   - 建 `dict` 缓存：方块字符串 → (翻译结果, 去括号结果, 是否排除)。schematic 百万格通常只有几十种唯一方块，翻译调用从 N 次降为几十次
   - 同样应用到 `schem_liquid` 和 `ImportWorld`

2. **流体邻居查询改字典**（`schem.py:296-325`）
   - 主遍历时顺手构建 `{(x,y,z): base_name}` 字典，`schem_liquid` 的 6 邻居查询改为纯字典查找（恢复 299-302 行注释掉的原设计），消灭每个流体格 6 次 `get_block`+翻译

3. **顶点/属性批量写入**（`schem.py:133-144`、`schem.py:685-695`、`codes/functions/mesh_to.py:179-188`、`importfile.py:966`、`schem.py:514+/579+` 的 separate 函数）
   - `from_pydata` → `mesh.vertices.add(n)` + `foreach_set('co', flat)`
   - 三个逐顶点循环 → `attribute.data.foreach_set('value'/'color', array)`
   - `re.escape(ids[i])` 移出循环：先按唯一字符串建 `{str: int}` 映射再批量转换

4. **litematic 路径小修**（`importfile.py:562-614`）
   - `_remove_brackets` 纯字符循环 → `s.split('[')[0]`
   - `_format_block_state` 结果按 BlockState 缓存
   - 边界计算的三重嵌套 min/max 生成器 → 一次遍历

5. **材质后处理收敛**（`importfile.py:257-267` 与 643-653 两份重复代码）
   - `register_blocks` 记录本次新建材质，只扫描这些材质；抽公共函数

6. **方块注册管线**（`codes/block.py:143-164`、`codes/functions/get_data.py`）
   - `bpy.ops.object.origin_set`/`transform_apply` → 直接矩阵变换 bmesh 顶点，消除 ops 场景更新开销
   - 恢复 `get_all_data` 被注释掉的缓存（get_data.py:49-51），`get_file_path` 结果缓存

## 第二档：结构性改造

7. **amulet chunk 级 numpy 读取**
   - 实现前先在 wheel 内核实 `level.get_chunk(cx, cz)` / `chunk.blocks`（numpy）/ `chunk.block_palette` 的确切 API 形态（`amulet/api/chunk/chunk.py`）
   - 流程：按 chunk 迭代 → palette 每个唯一 Block 翻译一次 → numpy 布尔掩码过滤排除方块 → `np.argwhere` 取坐标 → 向量化坐标变换 (x,-z,y) → foreach_set 一次写入
   - 若 API 不符预期则此步降级放弃并记录，保留第一档成果

8. **多进程合并去重**：`MultiprocessImport.execute`（importfile.py:640）的 `amulet.load_level` 在 cached=True 分支下不读方块，直接去掉；`schem_chunk` 同享翻译缓存

9. **`schem()` / `litematic_to_mesh()` 公共化**：两函数约 80% 重复（点云+属性+几何节点装配），抽公共装配函数，优化只做一处；顺带核查 schem.py:84-94 `nodes_modifier` 首次引用的潜在 NameError 问题

## 第三档：UX 与验证

10. **进度反馈**：长导入加 `wm.progress_begin/update/end`（光标转圈，成本极低）
11. **基准验证**：用大型 litematic（Blender 5.2）+ 大型 .schem（≤5.1 环境）做前后耗时对比，结果记入 `doc/performance-optimization.md`

## 约束与回退

- 行为完全不变：属性名（blockid/waterlogged/biome）、坐标系变换、`数字id#方块串` 命名、id_map 持久化格式严格保持（导出功能依赖这些约定）
- 每档独立提交、可单独回退；第 7 步有 API 验证前置，失败自动降级
- 实施顺序：第一档 → 基准 → 第二档 → 基准 → 第三档
