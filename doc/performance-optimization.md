# 性能优化指南 (Performance Optimization)

MBM-workflow 插件旨在处理大规模 Minecraft 地图数据。本指南介绍了如何优化导入、编辑和渲染性能。

## 1. 导入性能优化

### 导入管线内置优化（2026-08 重构）

导入代码在 2026-08 做了一轮系统性优化，所有路径自动生效，无需配置：

- **翻译结果缓存**：`.schem`/世界导入中，amulet 的 `from_universal` 翻译按唯一方块字符串缓存，百万格的翻译调用降为几十次；`get_version()` 查找移出循环。
- **chunk 级 numpy 批量读取**：优先走 amulet 的 `get_chunk_slice_box` 按 chunk 批量取调色板索引数组（每个 chunk 只翻译一次调色板，`argwhere` 一次取出全部保留格），彻底绕开逐格 `get_block` 的 Python 调用开销；API 不符时自动回退逐格路径。
- **流体两阶段处理**：`schem_liquid` 改为先批量收集流体格，邻居查询走稠密数组/字典命中，不再对每个流体格做 6 次 `get_block`+翻译（最坏 7N 次上游调用降为 N 次）。
- **litematic 批量读取**：直接读 Region 内部的调色板索引 numpy 数组，负尺寸区域的坐标平移与 litemapy 内部映射互逆；畸形文件的恢复路径也改为 numpy 批量位解码。
- **点云批量写入**：顶点坐标、`blockid`/`waterlogged`/`biome` 属性统一走 `vertices.add` + `foreach_set`，`re.escape` 按唯一字符串预先映射，替代逐顶点 Python 循环。
- **材质/模型缓存**：`get_file_path` 结果按 config 指纹缓存（只缓存命中结果），`get_all_data` 恢复模型缓存（命中返回浅拷贝，避免调用方原地修改互相污染）。
- **几何节点组复用**：同会话多次导入复用 "Blocks" 节点组，不再每次追加产生 `Schem.001`/`Blocks.001` 泄漏。

实测数据（`新手法教堂1.litematic`，161,186 个方块，Blender 5.2.1 后台模式）：

| 阶段 | 优化前 | 优化后 | 提速 |
|---|---|---|---|
| Schematic.load（含畸形区域恢复） | 12.4s | 2.1s | 5.9x |
| 方块字典预处理（逐格 → numpy） | 9.0s | 1.7s | 5.5x |
| 点云网格构建+属性写入 | 0.23s | 0.19s | ~1.2x |
| **完整导入（含方块注册）** | **26.6s** | **8.2s** | **3.2x** |
| 同会话二次导入 | 崩溃/泄漏 | 4.5s | — |

注：方块注册（模型 JSON 解析 + bmesh 构建）约 3.5s，与 temp/ 资源包完整度相关，未在本轮优化范围内；`.schem`/世界路径的 chunk 级批量读取在 Blender ≤5.1（amulet 可用）环境下生效，5.2 下 amulet 不可用时这些路径整体禁用。

### 多进程并行处理
当导入的 `.schem` 文件方块数量超过阈值（默认 100 万）时，插件自动启用多进程并行导入：
- **自动触发**: 导入 .schem 文件时自动判断，无需手动操作。
- **工作原理**: 沿 X 轴将数据均分为 N 个区块（N = 进程数），启动多个 Blender 后台实例并行处理，完成后自动合并。
- **配置**: 在插件偏好设置中可调整：
  - `ProcessNumber`: 最大进程数（默认为 CPU 核心数的一半）
  - `MinSize`: 触发多进程的最小方块数阈值（默认 1,000,000）
- **手动触发**: 也可直接调用 `bpy.ops.mbm.multiprocess_pool(filepath='...')`。
- **注意事项**: 多进程模式会占用更多内存（每个子进程独立加载 amulet 库），确保系统有足够的可用内存。
- **推荐做法**: 在导入面板勾选 **”按区块分离” (Separate by Chunk)**。这会将大地图拆分为多个小对象，虽然对象数量增加，但能避免单个网格过大导致 Blender 编辑模式卡死。

### 内存管理
- **关闭撤销 (Undo)**: 对于极大型导入（如 > 1GB 文件），建议在 Blender 设置中临时减少 Undo Steps，释放内存。
- **清理缓存**: 定期删除插件目录下的 `temp/` 和 `schemcache/` 文件夹，防止临时文件占用过多磁盘空间。

## 2. 网格优化 (Mesh Optimization)

这是提升渲染帧率（FPS）最关键的步骤。

### 合并重叠面 (Merge Overlapping Faces)
Minecraft 地图中，相邻方块之间存在大量不可见的接触面。
- **原理**: 算法检测两个面是否位置重合且法线相反。
- **操作**: 选中对象 -> 侧边栏 -> 导入面板 -> 点击 **“合并重叠面”**。
- **效果**: 通常可减少 40% - 60% 的多边形数量。

### 顶点合并 (Weld)
- **操作**: 在导入前勾选 **“合并重叠顶点”**。
- **作用**: 移除重复顶点，使网格拓扑更干净，有利于后续的平滑着色或物理计算。

### 几何节点烘焙
- **原理**: 默认情况下，方块是通过几何节点实时实例化的。这在编辑时很灵活，但对显卡压力大。
- **优化**: 如果不需要再编辑方块类型，可以应用 (Apply) 几何节点修改器，将其转为静态网格，大幅提升视口性能。

## 3. 渲染性能优化

### 视口显示
- **剔除流体**: 水和岩浆通常占据大量面数。如果只是为了预览建筑，可以在 `classification_files/block_type.py` 中调整过滤列表。
- **降低实例密度**: 对于树叶等大量重复的物体，可在几何节点中设置距离剔除（LOD）。

### 材质优化
- **纹理合并**: 插件默认为每个方块生成独立材质。对于超大型场景，建议使用 Blender 的烘焙功能将材质合并为一张图集 (Atlas)，减少 Draw Calls。

## 4. 开发者建议

如果你在编写脚本扩展本插件：

### 避免全网格遍历
不要在 Python 循环中遍历 `mesh.vertices`。
- **错误**: `for v in mesh.vertices: ...` (Python 层面循环慢)
- **正确**: 使用 `foreach_get` 和 `foreach_set` 结合 NumPy 进行批量数据操作。

### 使用合适的数据结构
- 对于颜色最近邻匹配，使用 `mathutils.kdtree.KDTree`（如 `paint_block`）。
- 对于整数网格坐标的精确查找，优先使用哈希字典（如方块笔刷的坐标索引）。

```python
# 示例：高效构建 KDTree
kd = KDTree(len(target_colors))
for i, color in enumerate(color_list):
    kd.insert(Vector(color), i)
kd.balance()
```
